## Reading (directional, n=1)

- ideas was 8x lighter on the user (48 vs 387 burden tokens; 9 vs 31 turns) and its honesty
  machinery did exactly what it was designed to do: 0 silent assumptions vs 2, and the judge's
  assumption_honesty scored 5.0 vs 2.0, carrying the composite win.
- But ideas under-elicited badly on this scenario: 8 questions vs 19, active elicitation 30% vs
  50%, and critical-fact coverage 17% vs 67%. It flagged what it didn't know instead of asking.
  If this pattern holds at scale, the scope-sizing/wave budget is too aggressive: honesty about
  gaps is not a substitute for closing them.
- ideas also spent 38% MORE assistant tokens despite fewer turns -- its turns are heavy (spec +
  ledger writing). The "token-lean" claim did not hold on this scenario as measured.
- Harness caveats all apply (prose-mode variant, same-family judge, sim-user relativity).

## Follow-ups suggested by this run

1. Product: revisit ideas' wave budgets / draft-early behavior -- consider a floor tied to
   critical-fact-shaped ambiguity (the interview should not close with obvious criticals unasked).
2. Harness: none new -- the dry-run segregation, header honesty, and version-parsing fixes from
   this shakedown are in.
3. Re-run this scenario (and the other five) with 3 runs per cell for a real pilot verdict.
